## Data and observation unit

One observation is an active source in a non-overlapping 250 ms causal window. A fixed 20 ms holdback lets the capture reader finish already arrived packets; it contributes to response time. Twelve numeric features are declared in online/features.py: log packet/byte rates, mean/std frame length and interarrival time, SYN/ACK/RST fractions, log count of source ports, mean TCP payload length and fraction of packets carrying payload. No address, port value, payload content, source/episode identifier or label enters the model.

Raw Ethernet frames use kernel SO_TIMESTAMPNS timestamps and nanosecond PCAP storage. Offline recomputation must reproduce live vectors. TCP stream reassembly associates PUBLISH messages with independently planned generator IDs and message byte ranges. A window is positive when it contains bytes of an independently designated malicious PUBLISH; legitimate sources remain benign during attack episodes. A message spanning windows marks every window containing its bytes. ACK-only windows are not labelled attacks merely because an episode contains an attack. Payload markers support reconciliation only and do not enter feature values.

Predeclared plan data/online/episode-plan.json v2 has 3 commissioning, 36 training, 12 validation and 12 test episodes with disjoint traffic seeds. No mitigation changes training/validation/test capture data. Source roles and low/medium/high offered attack rates vary independently within splits; onset phase is randomized relative to window boundaries. Legitimate burst traffic is included. Do not remove ambiguous or repeated feature vectors. Fit preprocessing only on training episodes; choose checkpoints/thresholds on validation episodes. Use the final test once per fixed recipe. Episodes, not packets/windows, are the generalization and systems replication units.

## Controlled workload and topology

Three MQTT publishers send a precomputed offered message schedule to an edge gateway; the gateway forwards to a protected Mosquitto broker and subscriber. Planned, attempted, socket-accepted and delivered messages are recorded separately. More than 50 ms overdue scheduled messages are recorded as generator/backpressure skips rather than silently shifting offered load. Same workload seeds/configurations are used across matched system conditions. Payload sizes are equal across roles within an episode. This is a publish-flood workload, not broad attack coverage.

Docker bridge isolation required explicit DNAT/SNAT inside the edge namespace: publishers connect to 172.30.95.2:1883, DNAT forwards to 172.30.96.3, and egress SNAT uses 172.30.96.2. The dedicated FORWARD chain matches original publisher source addresses before SNAT. Ingress capture retains original identities; broker/subscriber attribution uses independent application message IDs, never a claim that post-NAT source IP identifies the publisher. Data, protected, controller and management networks are externally isolated; no host ports or Docker socket are exposed.

Edge capture, window formation, preprocessing and CPU detector run on the actual traffic. Local mode authorizes and installs source-scoped FORWARD DROP. Central mode sends flagged edge alerts over a warmed persistent RPC for controller authorization, then uses the same local enforcement helper. This is controller authorization of alerts, not moving inference or every allow decision to the controller. No-mitigation still observes and scores traffic but applies no rules. Thresholds are identical. TTL is 1 s; historical DROP counters are saved before expiry and stop. Controller failure is fail-open with a 1 s timeout and no fallback/retry. Epoch/request checks prevent late responses acting in another episode.

## Detector recipes

Compare centralized MLP/GRU-Attention, FedMLP IID/non-IID and FedGRU non-IID over the 12 feature positions. GRU is not a temporal sequence model. Fixed30 passes/rounds, AdamW lr0.001, batch64, weighted BCE, all five simulated clients, one local pass, sample-weighted FedAvg. Three training seeds. Non-IID FedMLP additionally uses three partition seeds (Dirichlet alpha0.3 by binary label); partition variation is reported separately from initialization variation. Select checkpoints by validation average precision, then choose thresholds on CPU to maximize validation F1 subject to validation FPR<=1%. Apply the same rule to a simple packet-rate threshold baseline. Three training seeds and the partition grid are21 neural runs plus the rate baseline. Local optimizers reset per FL round whereas centralized optimizer state persists; recipe differences cannot be attributed solely to data placement. MLP is primary for system deployment, fixed non-IID partition42/training42 independently of test scores. No claim that ML beats a rate threshold is assumed.

## System episodes and measurements

Sixty episodes are fixed before evaluation: nine independent workload seeds covering three rates, none/local/central at nominal control delays0/50 ms, plus three outage workloads ×local/central. Mode/condition order is randomized. Outage is actual100% packet loss on the edge control interface, introduced after normal RPC warmup/calibration. Management and data paths remain unaffected.

Report attack-onset-to-command response (kernel ingress timestamp of first reconciled malicious message bytes), feature accumulation/holdback, queue/inference/controller/enforcement components, rule counter evidence and actual service delivery. A missed attack has no successful response latency and remains in the coverage denominator. Report planned/attempted/accepted/delivered legitimate messages, delivery latency, attacking messages reaching subscriber, normal-source false blocks, recovery and CPU/RAM. Fixed command-return endpoint is an installation upper bound. All containers share one kernel boot ID and equal monotonic time-namespace offsets, verified before episodes; record realtime/monotonic conversion uncertainty. Independent workload episodes, not repeated messages or model seeds alone, define systems replicates.

This single virtualized, synthetic MQTT publish-flood test does not establish production hardware performance, unseen attack-family coverage, true privacy guarantees or deployment on an actual municipal utility.
